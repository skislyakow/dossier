# 0004 — Fetch-адаптер: одна политика кэша и инжектируемый транспорт

Date: 2026-10-11
Status: Accepted
Decision-makers: владелец сайта (выбран последний кандидат архитектурного ревью — c3)

## Context

Данные портфолио/статистики приходят из трёх внешних API (GitHub, PyPI, PyPistats).
Раньше весь сетевой код жил в `main/badge_utils.py` рядом с резолверами бейджей:

- кэш-паттерн (get → set c `CACHE_OK`/`CACHE_FAIL`) копировался в три функции
  (`fetch_repo_data`, `fetch_pypi_data`, `fetch_github_stats`);
- таймаут и обработка ошибок были «впечены» в каждое место вызова;
- агрегация языков была заперта внутри сетевой функции, её нельзя было дёрнуть без HTTP;
- тесты ходили по миру через `mock.patch.object(badge_utils, '_get_json')` — мок транпорта, а не контракта.

Одну и ту же политику можно было бы случайно поправить в одном месте и забыть в другом.

## Decision

Выделена `main/fetch.py` — единый кэшированный fetch-адаптер (порт, по словарю
arch-ревью):

- `fetch(url, headers=None) -> json|None` — **единственная точка** политики TTL:
  успех → `CACHE_OK` (6ч), сбой → `CACHE_FAIL` (5мин, чтобы не долбить сдохший API).
  Промах от закэшированного `None` отличает sentinel `_MISS`.
- Транспорт инжектится через модульную глобаль `transport`: по умолчанию
  `UrllibTransport` (stdlib `urllib`, без зависимостей), тесты патчат
  `mock.patch.object(fetch, 'transport', MemoryTransport(...))` — in-memory адаптер
  поставляется в самом модуле (второй адаптер оправдывает seam).
- Агрегаторы `fetch_repo_data`/`fetch_pypi_data`/`fetch_github_stats` строят
  fan-out нескольких URL за своим интерфейсом и сами решают TTL комбинированного
  ключа (если **все** подзапросы упали — короткий кэш, иначе длинный),
  `aggregate_languages` — чистая трансформация (топ-5 языков в процентах).
- Служебное для GitHub (`GITHUB_TOKEN`, `_github_headers`) тоже переехало сюда —
  единственное место, где собираются auth-заголовки.
- `badge_utils` избавлен от сети: остались реестр `BADGE_SOURCES`, чистые резолверы
  и `enrich_project`, который импортирует данные из `fetch`.

## Consequences

- Политика кэша живёт один раз; таймаут/ошибки — один раз в `UrllibTransport`.
- Юнит-тесты адаптера не видят сети и не трогают реальный кэш: `_RecordingCache`
  проверяет TTL, `MemoryTransport` — fan-out и хедеры (`test_fetch.py`).
- Тесты представлений перешли с мока функции на мок контракта
  (`test_views.py`: `ApiProjectsEnrichTest`, `ApiGithubTest`) — больше не зависят
  от имени приватного `_get_json`.
- `aggregate_languages` тестируется напрямую без HTTP.
- Новый источник данных = новый агрегатор поверх `fetch()`; новая политика = одно
  изменение в одном месте. Если заболела вся сеть — правим только `fetch`/транспорт.
