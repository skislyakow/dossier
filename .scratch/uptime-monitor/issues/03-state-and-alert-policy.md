# 03: Состояние между прогонами и политика алертов

Status: ready-for-agent
Blocked by: 01, 02

**What to build:** Чистая функция «результаты проверок + прошлое состояние → список сообщений к отправке», плюс персист состояния `state.json` в ветке `state` репозитория (раннеры GitHub эфемерны).

## Решения

- `state.py`:
  - `load(path)`, `save(path, state)` — JSON, атомарная запись (tmp + rename).
  - `decide(state, results, now) -> (new_state, messages)` — без сети и без часов внутри (время инжектится).
- Политика:
  - `fails` считается по прогонам; DOWN-алерт — при `fails >= 2` **подряд** (первый неудачный прогон = «подозрение», тишина).
  - Пока DOWN: напоминание не чаще 1 раза в 60 мин.
  - Переход DOWN → UP: ровно одно RECOVERED с длительностью от `since`.
  - `cert_days < 14`: 🟡 один раз в сутки (`cert_warned_on` = дата).
  - Смена причины (timeout → HTTP 502) не порождает отдельный алерт, только обновляет `reason` (чтобы не спамить).
- Персист в workflow: checkout ветки `state` в `.state/`, прогон, `git add/commit` только если файл изменился, push с 1 retry (pull --rebase на конфликт). Ветка `state` создаётся при первом изменении, `main` не трогается.
- `concurrency: {group: uptime-probe, cancel-in-progress: false}`.

## Acceptance criteria

- [ ] Тесты с фиксированным `now`: 1-й fail → нет алерта; 2-й fail → DOWN; ещё 5 прогонов < 60 мин → тишина; через 61 мин → reminder; UP → ровно один RECOVERED с длительностью.
- [ ] Упал → поднялся → снова упал: снова DOWN-алерт (сброс `fails`/`since`), без дублей.
- [ ] cert 13 дней → предупреждение; повторный прогон в тот же день → тишина; на следующий день → снова.
- [ ] `save()` не оставляет битый файл при прерывании; загрузка отсутствующего файла = пустое состояние.
- [ ] Никаких сетевых вызовов в `decide`.
