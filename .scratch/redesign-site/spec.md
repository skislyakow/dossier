# Спека: полный redesign сайта портфолио

Status: ready-for-agent

## Problem Statement

Текущий сайт-визитка информативен, но визуально «аккуратно-нейтральный»: за первые секунды нет ни одного сильного запоминающегося момента, а декоративные элементы (терминал с typewriter, летающие призраки-иконки, печатающийся заголовок, двухколоночный hero) отвлекают от главного — проектов и экспертности. Рекрутер, открывший сайт, не получает мгновенного впечатления «инженер с продакшн-проектами и хорошим вкусом» и не может быстро просканировать проекты и навыки. Есть ощущение, что сайт сделан по шаблону dev-визиток.

Дополнительно: пользователь хочет полностью пройти инженерный skills-флоу (grill → spec → tickets → implement → code-review → retro), используя эту переделку как обучающий проект.

## Solution

Полная пересборка внешнего вида и честный рефакторинг кода поверх текущего стека (Django CMS + vanilla JS, zero-build, автодеплой):

- **Новый дизайн-язык**: bold editorial / brutalist typography — монохром + один акцентный цвет (кислотный лайм `#CDFF50`), крупная типографика, сетки, full-width Hero.
- **Signature-момент**: имя/специальность во всю ширину экрана со scroll-reveal — первое впечатление за 3 секунды.
- **Новая структура страницы**: Hero (одна колонка, позиционирование) → Projects → Опыт → Skills → Contact.
- **Усиленные карточки проектов**: таглайн + 3–4 конкретных буллета результата + динамические бейджи + ссылки, с умеренным magnetic-hover.
- **Skills по Категориям навыка**: сетка, сгруппированная по зонам экспертизы (Backend / Web / DevOps / Bots & Integrations / Tools).
- Убираются: терминал с typewriter, призраки, печатающийся заголовок, двухколоночный hero, облако `{ }`, часы MSK (живут в блоке терминала).
- Сохраняются: тёмная тема с переключателем (дефолт dark), курсорный градиент (приглушённо), GitHub stats toggle, back-to-top, hover-подписи соцсетей, бейджи с серверным кэшем, API-эндпоинты, автодеплой.
- Контент полностью на русском, правится через существующий админ.

## User Stories

1. As a рекрутер-наниматель, I want to увидеть в первые 3 секунды крупное имя и чёткую специальность («Python-разработчик: автоматизация, Telegram-боты и веб на Django»), so that сразу понять, кем этот человек является и стоит ли листать дальше.
2. As a рекрутер, I want to видеть секцию Projects сразу после Hero (а не после навыков), so that быстро оценить продакшн-опыт по репозиториям.
3. As a рекрутер, I want to читать каждый Проект как Усиленную карточку (таглайн + 3–4 буллета результата + бейджи + ссылки), so that получить ответы на «что сделал / какой результат / чем подтверждено» без перехода в репозиторий.
4. As a рекрутер, I want to видеть бейджи GitHub/PyPI (звёзды, версии, лицензии, даты) прямо в карточке, so that верить цифрам, а не прилагательным.
5. As a рекрутер, I want to просмотреть Опыт (хронологию карьеры) в читаемом современном виде, so that понять траекторию и длительность проектов.
6. As a рекрутер, I want to видеть навыки, сгруппированные по Категориям (Backend / Web / DevOps / Bots & Integrations / Tools), so that за секунду найти нужную зону («есть Django? есть Docker?»).
7. As a рекрутер, I want to получить три очевидных канала связи (email, Telegram, GitHub) крупной секцией Contact, so that написать одним движением, не ища футер.
8. As a посетитель-заказчик, I want to увидеть, что сайт современный, быстрый и сделан с вниманием к деталям, so that ассоциировать это качество с работой владельца.
9. As a посетитель, I want to, чтобы сайт работал на мобильном так же полно, как на десктопе, so that не терять контент при переходе с телефона.
10. As a посетитель, I want to переключать тёмную/светлую тему, so that читать сайт в удобном режиме (дефолт — тёмный).
11. As a посетитель, I want to видеть анимации (scroll-reveal, magnetic-hover, marquee) плавно и без лагов, so что сайт ощущался «живым», но не раздражал.
12. As a посетитель с prefers-reduced-motion, I want to отключать необязательные анимации, so that комфортно читать без движения.
13. As a посетитель, I want to быстро возвращаться наверх кнопкой back-to-top, so что не скроллить длинную страницу вручную.
14. As a посетитель, I want to видеть одну marquee-строку с технологиями между секциями, so что получать ритм и additional-контекст стека без отдельной секции.
15. As a Сергей (админ), I want to управлять контентом (Проекты, Навыки с категориями, Опыт, Контакты) через существующий Django admin, so что не трогать код для обновления сайта.
16. As a Сергей, I want чтобы новый навык после добавления в админке автоматически попадал в нужную Категорию на сайте, so что не править шаблоны вручную.
17. As a Сергей, I want чтобы вся типографика и иконки остались локальными (self-hosted), so что не было внешних запросов иCLS-флешей.
18. As a Сергей, I want чтобы старые фичи (GitHub stats toggle, бейджи с серверным кэшем) продолжали работать после редизайна, so что не потерять уже сделанное.
19. As a Сергей, I want чтобы деплой остался «push to main → живой сайт», so что не усложнять пайплайн.
20. As a посетитель, I want чтобы ссылки на проекты (репозиторий, PyPI, сайт) были заметными и кликабельными в каждой карточке, so что уйти в детали одним кликом.
21. As a рекрутер, I want чтобы Hover на карточке проекта давал тактильный отклик (magnetic), so что интерактив воспринимался как «сделано руками», а не шаблоном.
22. As a Сергей, I want чтобы весь текст сайта был на русском языке, so что говорить с целевой аудиторией без переводных штампов.
23. As a посетитель, I want чтобы страница быстро грузилась (без сборщика, локальные шрифты, ленивые картинки), so что не закрыть от ожидания.
24. As a Сергей, I want пройти полный skills-флоу (spec → tickets → implement по одному тикету → code-review → retro) на этой переделке, so что научиться использовать навыки на реальном проекте.
25. As a агент, I want иметь обновлённый AGENTS.md в конце, so что следующие сессии работали с актуальным описанием проекта.

## Implementation Decisions

- **Стек не меняется**: Django 6 + vanilla JS + CSS без сборщика; автодеплой (GitHub Actions → VPS) сохраняется. Решение (1b из grilling): новый дизайн + честный рефакторинг, не стек-сброс.
- **Язык всего контента — русский**; двухязычность не делается.
- **Тема**: дефолт dark, существующий переключатель light сохраняется (localStorage).
- **Дизайн-система**: монохром + один акцент (кислотный лайм `#CDFF50`, запасной — оранжевый); шрифты и Material Symbols — уже локальные subset'ы, используются как есть.
- **Hero**: одна колонка, full-width oversized-типографика имени/роли + scroll-reveal (IntersectionObserver), приглушённый курсорный градиент, строка позиционирования «Python-разработчик: автоматизация, Telegram-боты и веб на Django».
- **Удаляются** (по таблице Раунда 2): терминал с typewriter и часы MSK, призраки (ghost.js), печатающийся заголовок (typing.js), двухколоночный layout, облако навыков в curly-формате.
- **Секции в порядке**: Hero → Projects → Опыт → Skills → Contact.
- **Проекты** показываются как Усиленная карточка; магнетик-hover умеренный; стагger-reveal при скролле остаётся как акцент.
- **Опыт**: текущий таймлайн-механизм рендеринга сохраняется, визуально переработывается в секцию.
- **Навыки**: в модель Skill добавляется поле `category` (choices: Backend / Web / DevOps / Bots & Integrations / Tools), редактируется в админке; data-migration по паттерну `0008` назначает категории существующим 36 навыкам; API навыков отдаёт `category`; секция рендерит сетку, сгруппированную по Категориям.
- **Marquee**: одна строка технологий между секций, CSS-анимация с учётом prefers-reduced-motion.
- **Contact**: три канала — email, Telegram, GitHub; модель ContactInfo расширяется типом `github`.
- **Контент остаётся в CMS**: 3 существующих Проекта, правки текстов — через админ.
- **Рендеринг в JS**: при переписывании вывода данных (карточки, таймлайн) — экранировать значения (закрывает известный ToDo про innerHTML/XSS).
- **Доступность**: все необязательные анимации уважают prefers-reduced-motion; сохраняются aria-labels.

## Testing Decisions

- **Хороший тест** проверяет внешнее поведение через HTTP, а не внутренности: статусы, наличие секций в HTML, JSON-контракт API. Реализация — Django test client, без сети (моки внешних API).
- **Главный (и единственный) шов** — ответы Django-вьюх: `/`, `/api/skills/` (новое поле `category`), `/api/projects/` (контракт не меняется), `/api/github/`.
- **Приоритетные тесты** (паттерн уже в коде): расширение существующих view/API-тестов — проверка рендера главной (секции присутствуют) и обогащённого контракта навыков с категориями; существующие тесты бейджей/статистики не ломаются.
- **JS/CSS автотестов нет** (zero-build, харнесса нет) — визуальная проверка на dev-сервере по чек-листу перед каждым тикетом-деплоем.

## Out of Scope

- `og:image` / `twitter:image` (SEO-туду остаётся отдельной задачей).
- Миграция стека, сборщики (Vite/webpack), фреймворки (React/Vue/HTMX), GSAP/Three.js.
- Двуязычность / переключатель языка.
- Полноценные кейсы (проблема→решение→в сотни слов) вместо Усиленных карточек.
- LinkedIn, VK и новые каналы связи сверх email/Telegram/GitHub.
- Автотесты JS.
- Уровни/оценки навыков (junior/middle/senior, бары).
- Изменения инфраструктуры, деплоя, nginx/gunicorn.
- Удаление или переезд существующих данных CMS.

## Further Notes

- **Образовательная цель**: тикеты режутся tracer-bullet и гоняются по одному (`/implement` → `/clear`), первый тикет — в текущей сессии как демонстрация механики; в конце — `code-review`, `retro` и переписывание AGENTS.md.
- Словарь проекта зафиксирован в `GLOSSARY.md` (Проект, Усиленная карточка, Signature-момент, Категория навыка, Опыт) — спека и тикеты используют эти термины.
- Запасной акцентный цвет (оранжевый) можно включить одной правкой токена, если лайм покажется кричащим.
