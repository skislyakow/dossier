# 09: Облако тегов проектов

**What to build:** У Проекта появляется поле `tags` — курируемые короткие метки (Django, aiogram, Redis, systemd…). В секции Projects теги показываются облаком в curly-формате `{ tag: n }`, где кегль растёт с частотой тега (сколько Проектов его несут). Тег, которого нет ни в одном опубликованном Проекте, в облаке не появляется. Клик по тегу фильтрует список проектов до тех, что несут этот тег (одиночный выбор, `All` — сброс). Существующий фильтр по типу разработки (роли) остаётся отдельной фичей и не заменяется.

## Comments

### 2026-10-09: решения по обсуждению

- **Источник тегов** — новое поле `tags` (не GitHub-языки и не `features`): курируемые метки, задаются в админке.
- **Формат** — curly `{ tag: n }` с варьирующим кеглем (переиспользовать существующий curly-компонент `.tag`/`.tag-xl|lg|md|sm`).
- **Выбор** — одиночный.
- **Роль не трогаем**: `portfolio-cats` (фильтр по типу разработки) остаётся отдельным функционалом, облако тегов — независимая фича.
- В GLOSSARY добавить термин **«Тег проекта»** при реализации (доменный словарь проекта).
- Мелкий фикс из этого же обсуждения (кегль подписей рельса `0.65rem → 0.8rem`) сделан отдельно и записан в тикет 02.
